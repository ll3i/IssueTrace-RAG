## Ⅰ. 플랫폼 개요 및 배경

### 1. 개발 배경 및 목적

#### 1) 제조 현장의 AI 도입 실태
우리나라 제조업은 세계적 수준의 생산 경쟁력을 보유하고 있지만, 현장 단위 AI 도입은 아직 제한적이다. 중소 제조기업의 AI 도입률은 1% 수준에 머물고 있으며, 전체 제조업의 AI 활용률도 서비스업 대비 낮은 수준이다. 많은 기업이 AI의 필요성은 인식하고 있지만 실제 도입과 운영으로 이어지지 못하는 인식-행동 간 격차가 크게 나타난다.

이 간극의 원인은 단순히 기술 부재가 아니라 도입 구조의 문제에 가깝다. 제조 현장에서는 이미지, 센서값, 공정 조건, 작업 이력 등 활용 가능한 데이터가 이미 존재하지만, 이를 실시간 판단과 원인 분석, 공정 개선으로 연결할 수 있는 인력과 시스템이 부족하다. 결국 데이터는 쌓이지만 활용되지 못하고, 불량이 발생하면 숙련자의 경험과 수작업 분석에 의존하는 방식이 반복된다.

#### 2) 도입 지연의 구조적 원인
제조 현장의 AI 도입을 가로막는 장애 요인은 비교적 명확하다.

| 장애 요인 | 설명 |
|------|------|
| 전문 인력 부족 | 데이터 수집, 모델 운용, 공정 적용을 동시에 이해하는 인력이 부족 |
| 초기 도입 비용 부담 | 신규 시스템 구축, 장비 교체, 외부 솔루션 도입 비용이 큼 |
| 전략 부재 | AI를 어디에 어떻게 적용할지에 대한 현장형 설계가 부족 |
| 데이터 활용 체계 부족 | 품질 데이터는 있으나 이를 분석하고 피드백하는 루프가 없음 |
| 사후 대응 중심 운영 | 불량 판정 후 원인 추적과 개선 제안이 분리되어 반복 불량 발생 |

특히 중소·중견기업에서는 검사와 분석, 보고, ERP 연계가 분절적으로 운영되는 경우가 많다. 검사 결과는 파일로 저장되고, 원인 판단은 숙련자가 별도로 해석하며, 보고는 수기로 작성되고, 전산 반영은 다시 수작업으로 입력된다. 이 비효율을 줄이지 못하면 AI는 단순 PoC 수준에서 멈추게 된다.

#### 3) 정부 정책 방향과 제안의 필요성
정부는 제조 AX 확산과 스마트공장 고도화를 주요 정책 과제로 추진하고 있다. 제조 AI 모델 개발, AI팩토리 보급, 중소 제조기업의 현장형 AI 도입 확대가 중요한 목표로 제시되고 있다. 따라서 필요한 것은 범용 AI가 아니라 제조 현장에 바로 연결 가능한 실무형 플랫폼이다.

본 제안은 이러한 정책 방향과 맞물린다. 비전 검사 이미지, 설비 정보, 판정 결과를 통합하고, AI가 불량 판정에서 끝나지 않고 원인 추정과 조치 제안까지 이어지도록 설계함으로써 제조 현장의 구조적 AI 도입 장벽을 낮추는 것을 목표로 한다.

#### 4) 개발 목적
본 아이디어의 핵심 목적은 단순한 불량 탐지 AI를 넘어, 불량 판정에서 자기검증, 원인 추정, 조치 제안까지 이어지는 공정형 AI Agent를 구현하는 데 있다.

구체적 목적은 다음과 같다.

| 목적 | 내용 |
|------|------|
| 판정 자동화 | 비전 검사 이미지와 메타데이터를 기반으로 불량 여부를 신속 판정 |
| 자기검증 강화 | CoVe 구조를 통해 AI가 스스로 판단을 재검토하도록 설계 |
| 원인 추정 지원 | 단순 불량 라벨링이 아니라 공정 이상 원인을 해석 가능한 형태로 제시 |
| 조치 제안 연결 | 엔지니어가 바로 활용할 수 있는 개선 방향과 확인 포인트 제공 |
| 현장 도입성 확보 | 기존 이미지 폴더, CSV 로그, 온프레미스 환경을 그대로 활용 |
| 경험 자산화 | 반복 불량 패턴과 조치 결과를 누적해 조직 지식으로 전환 |

즉, 본 플랫폼은 검사 AI, 분석 도구, 보고 자동화, 시스템 연계를 하나의 흐름으로 묶어 제조 현장의 실제 의사결정을 돕는 것이 핵심이다.

### 2. 시스템 구성 개요

#### 1) 전체 아키텍처
플랫폼은 Streamlit 기반 단일 웹 서비스 위에서 동작하며, 6개 핵심 탭을 중심으로 기능이 구성된다. 사용자는 하나의 인터페이스에서 검사 결과 확인, 원인 검토, 파라미터 조정, 일일 보고서 생성, 실시간 모니터링, ERP 전송까지 수행할 수 있다.

구성 요소는 크게 네 계층으로 나뉜다.

| 구성 계층 | 주요 역할 |
|------|------|
| Web Service | 6개 탭 기반 통합 UI, 사용자 입력, 시각화 |
| AI 판정 엔진 | GPT-4o 기반 멀티모달 분석, CoVe 자기검증, VQA 응답 |
| 데이터 레이어 | CSV 검사 로그, JSON 메타데이터, 이미지 폴더 관리 |
| 연동 인터페이스 | Mock ERP API, JSON 전송, CSV 백업 다운로드 |

이 구조는 별도 대규모 인프라 없이도 현장 PoC와 확장이 가능하도록 설계되었다. 특히 파일 기반 로그와 이미지 폴더 연동을 활용해 기존 검사 장비를 교체하지 않고도 적용할 수 있는 것이 장점이다.

#### 2) 주요 입력 데이터

| 데이터 유형 | 형식 | 설명 |
|------|------|------|
| 검사 결과 로그 | `explanations.csv` | ID, confidence, valid, reason, roi_box, sub_boxes 등 포함 |
| 검사 이미지 | PNG/JPG 폴더 | ROI 및 서브박스 좌표 기반 동적 렌더링 대상 |
| 파라미터 설정 | 런타임 슬라이더 | Confidence cutoff, CLAHE, Sharpen Factor 조정 |
| LLM API | Runtime API Key | GPT-4o 연동, VQA 챗봇 및 보고서 생성 |

주요 특징은 정형 데이터와 비정형 이미지 데이터를 동시에 다룬다는 점이다. 즉, 단순히 이미지만 분석하는 시스템이 아니라 검사 로그와 판단 사유, 처리 이력까지 함께 반영하는 멀티모달 제조 AI Agent 구조다.

## Ⅱ. 6대 핵심 기능 명세

### 1. 사진 검사 (Visual Inspection & VQA)

#### 1) 기능 개요
사진 검사는 개별 불량 파트를 심층 분석하는 핵심 공간이다. 사용자는 특정 샘플을 선택하고, 원본 이미지 위에 ROI 박스와 서브박스가 오버레이된 화면을 보면서 AI 판정 결과를 검토할 수 있다. 단순히 이미지를 보는 기능이 아니라, AI가 어떤 위치를 기준으로 어떤 판단을 했는지 함께 확인할 수 있다는 점이 중요하다.

#### 2) 주요 기능

| 기능 | 설명 |
|------|------|
| 동적 이미지 렌더링 | ROI 및 Sub-box 좌표 기반 실시간 박스 오버레이 |
| 메타데이터 카드 | Confidence, 재판독 결과, 튜닝 적용 여부, 판독 요약 표시 |
| JSON 토글 | 원문 JSON을 즉시 노출/숨김 전환 |
| 실시간 재판독 | 현재 샘플에 대해 LLM 판독을 즉시 재실행 |
| VQA 챗봇 | 이미지와 메타데이터를 프롬프트화해 자유 질의응답 제공 |

#### 3) 사용 시나리오
예를 들어 엔지니어가 `TEST_007` 샘플을 선택하면 이미지에 ROI 박스가 자동 렌더링되고, Confidence 0.42와 같이 낮은 판정 신뢰도가 표시된다. 사용자는 "H2 핀 단선이 맞는지 다시 확인해 줘"와 같은 질문을 입력해 VQA 챗봇으로 추가 검증을 수행할 수 있다. 이후 실시간 재판독 버튼을 누르면 CoVe 검증을 포함한 결과가 즉시 다시 반환된다.

이 기능의 차별점은 단순 이미지 뷰어가 아니라, AI 판단 과정에 사용자가 직접 개입하고 근거를 확인할 수 있는 인터랙티브 구조라는 점이다.

### 2. 통합 대시보드 (Global Dashboard)

#### 1) 기능 개요
통합 대시보드는 전체 기간 누적 검사 데이터를 거시적으로 분석하는 관리자·경영진용 화면이다. 개별 샘플 확인이 아니라 품질 현황, 불량 추세, AI 판정 안정성, 자가검증 빈도 등을 한 번에 파악할 수 있도록 설계되었다.

#### 2) 상단 KPI 지표

| 지표명 | 설명 | 표시 형식 |
|------|------|------|
| 총 검사 건수 | 전체 누적 검사 샘플 수 | 정수 카운터 |
| 정상/불량 건수 | Normal / Abnormal 분류 결과 | 건수 + 불량률 |
| 전체 평균 신뢰도 | AI 판단 confidence 평균값 | 소수 2자리 + 백분율 |

#### 3) 6종 차트 구성

| 차트명 | 분석 목적 | 유형 |
|------|------|------|
| 양품 vs 불량 비율 | 기초 수율 현황 파악 | 파이/도넛 차트 |
| API 요청 유효성 | API 및 통신 상태 모니터링 | 누적 막대 차트 |
| 세부 불량 요인 분석 | H1/H2/H3 단선, 패키지 손상 등 결함 유형 비교 | 수평 막대 차트 |
| 판독 확신도 추세선 | 모델 예측 안정성 시계열 추적 | 꺾은선 차트 |
| 다수결 재검사 발동 빈도 | used_vote 기준 난이도 높은 케이스 빈도 확인 | 막대 차트 |
| CoVe 사용 빈도 | AI 자가교정 로직 발동 횟수 확인 | 막대 차트 |

이 대시보드는 단순 통계 시각화가 아니라 AI 운영 품질까지 함께 보여준다. 예를 들어 confidence가 지속적으로 하락하거나 CoVe 발동 빈도가 증가하면, 이는 현장 데이터 난이도 변화나 판정 불안정성을 의미할 수 있다.

### 3. 튜닝 랩 (Threshold & Vision Processing)

#### 1) 기능 개요
튜닝 랩은 엔지니어가 AI 판정 기준과 이미지 전처리 파라미터를 현장 데이터 기준으로 조정해 볼 수 있는 실험 공간이다. 운영 중인 라인에서 임계값을 갑자기 바꾸기 전에 수율에 미치는 영향을 시뮬레이션할 수 있어 실무 활용성이 높다.

#### 2) AI 임계값 시뮬레이터
Confidence cutoff 슬라이더를 통해 0.50~0.99 범위에서 판정 기준을 조정할 수 있다. 예를 들어 cutoff를 0.95에서 0.99로 높였을 때 pass/fail 비율이 어떻게 바뀌는지 즉시 차트로 확인할 수 있다. 이를 통해 수율과 불량 검출 민감도 사이의 균형을 현장 조건에 맞게 잡을 수 있다.

#### 3) 비전 프로세싱 놀이터
이미지 전처리 측면에서는 CLAHE 강도와 Sharpen Factor를 슬라이더로 조정하면서 원본 이미지와 보정 이미지를 나란히 비교할 수 있다. 신규 불량 유형 탐지 실패 시 적절한 대비 보정과 선명도 조정값을 찾는 데 유용하다.

| 조정 항목 | 목적 |
|------|------|
| Confidence Cutoff | 판정 기준 민감도 조절 |
| CLAHE | 저대비 이미지 개선, 경계 인식 보조 |
| Sharpen Factor | 핀, 외곽선, 미세 결함 가시성 강화 |

튜닝 랩은 경험적 조정에 의존하던 기존 방식을 데이터 기반 시뮬레이션으로 바꾼다는 점에서 의미가 있다.

### 4. 데일리 보고서 (Automated Daily Report)

#### 1) 기능 개요
데일리 보고서는 검사 결과를 바탕으로 일일 품질 리포트를 자동 생성하는 기능이다. 기존에는 엔지니어가 검사 건수, 결함 유형, 평균 신뢰도, 특이사항을 수작업으로 정리해야 했지만, 본 기능은 이를 자동화한다.

#### 2) 보고서 생성 프로세스

| 단계 | 설명 |
|------|------|
| KPI 수집 | 당일 검사 건수, 결함 유형별 빈도, 평균 신뢰도, CoVe 발동 횟수 수집 |
| 프롬프트 구성 | 수집 KPI를 구조화된 문단으로 정리해 LLM 입력 생성 |
| 보고서 생성 | 경영진 친화적인 문체의 Markdown 리포트 자동 생성 |
| 내보내기 | `.md` 파일 즉시 다운로드 |

보고서는 단순 요약을 넘어서, 당일 품질 흐름과 주요 이슈를 빠르게 파악할 수 있는 형태로 제공된다. 이를 통해 엔지니어는 서술 작업에 쓰던 시간을 공정 개선과 원인 분석에 재투자할 수 있다.

### 5. 실시간 모니터링 (Line Streaming Alert)

#### 1) 기능 개요
실시간 모니터링은 0.5초 단위로 가상 검사 데이터가 유입되는 스트리밍 상황을 재현해 라인 품질 이상을 빠르게 감지하는 기능이다. 실제 생산 라인에서는 누적 품질 저하가 한동안 드러나지 않다가 뒤늦게 발견되는 문제가 많기 때문에, 단기 불량률 기반 조기 경보는 실효성이 높다.

#### 2) 동작 방식
시스템은 가상 데이터 스트림을 순차 반영하면서 누적 불량률과 단기 불량률을 실시간 차트로 업데이트한다. 단기 불량률이 일정 기준을 넘으면 차트 색상과 경고 메시지로 즉시 알려준다.

| 알림 레벨 | 발동 조건 | 화면 변화 |
|------|------|------|
| 정상 | 단기 불량률 30% 미만 | 차트 정상색 유지 |
| 경고 | 단기 불량률 30% 이상 | 차트 경고색 전환 + 비상 알림 텍스트 표시 |

이 기능은 사후 리포트 중심 대응에서 벗어나 선제 대응 중심 운영으로 전환하는 기반이 된다.

### 6. ERP 연동 (Mock ERP Sync)

#### 1) 기능 개요
ERP 연동 기능은 불량 판정 데이터를 선별해 외부 시스템으로 전송하는 실무 연계 영역이다. 현재는 Mock ERP API 구조를 사용하지만, 실제 MES/ERP 엔드포인트로 쉽게 교체 가능한 형태로 설계되었다.

#### 2) 주요 기능

| 기능 | 설명 |
|------|------|
| 선택 전송 테이블 | Abnormal 데이터 그리드 표시 및 체크박스 선별 전송 |
| Valid 컬럼 확인 | 엔지니어가 현장 검수 결과를 직접 체크 |
| Mock ERP 전송 | 선택 항목을 JSON payload로 직렬화해 전송 |
| 동기화 로그 | 전송 완료 이력을 시간 기준으로 누적 표시 |
| CSV 백업 | 선택 데이터의 오프라인 백업 파일 즉시 다운로드 |

이 구조는 현장 검수를 거친 데이터만 ERP로 반영할 수 있게 해, AI 판정 결과를 무조건 시스템에 넣는 것이 아니라 사람 검토와 연계된 운영 방식을 지원한다.

## Ⅲ. 기술 스택 및 구현 방향

### 1. 핵심 기술 스택

| 기술 레이어 | 적용 기술 | 역할 |
|------|------|------|
| 웹 프레임워크 | Streamlit | 6탭 단일 페이지 인터페이스, 실시간 상태 관리 |
| AI 판정 엔진 | GPT-4o | 이미지 + 텍스트 동시 분석, VQA 챗봇 |
| 자기검증 구조 | CoVe | AI 불확실 판정 시 재검증 로직 구동 |
| 이미지 처리 | OpenCV | CLAHE, Sharpen 등 전처리 실시간 적용 |
| 데이터 관리 | Pandas + CSV | 검사 로그 로딩, 필터링, 직렬화 |
| 보고서 생성 | LLM + Markdown | KPI 자동 요약 및 일일 보고서 생성 |
| ERP 연동 | Mock REST API + JSON | 실제 MES/ERP 교체 대응 가능 구조 |

### 2. 구현 방향

#### 1) 모듈성
6개 기능을 독립 탭으로 분리해 특정 기능 변경이 다른 모듈에 미치는 영향을 최소화했다. 또한 ERP 연동도 Mock API 기반으로 분리해 실제 시스템 교체 시 엔드포인트와 포맷 변경만으로 대응할 수 있게 했다.

#### 2) 현장 적용성
기존 검사 장비가 생성하는 이미지 폴더와 CSV 로그 형식을 그대로 활용하도록 설계해 신규 설비 교체 부담을 줄였다. 또한 엣지 또는 온프레미스 배포를 고려해 제조 데이터 외부 유출 리스크를 최소화했다.

#### 3) 확장성
임계값, 경고 조건, 차트 기준, 필터 기준 등을 파라미터화해 라인별 맞춤 조정이 가능하다. 향후 멀티 라인 또는 공장 단위 확장 시 데이터 레이어와 연동 인터페이스 중심으로 확장이 가능하다.

#### 4) 신뢰성
본 플랫폼은 생성형 AI를 사용하지만, 무근거 자동화가 아니라 자기검증과 근거 제시를 강조한다. 이미지 기반 판정 결과를 메타데이터와 함께 보여주고, CoVe 구조로 재검토하며, 사람이 검수 후 ERP에 반영하게 함으로써 AI 결과의 운영 신뢰성을 높였다.

이 수치는 단순 편의성 개선이 아니라 현장 운영 방식의 전환을 의미한다. 엔지니어는 반복 보고와 단순 조회보다 원인 분석과 공정 개선에 더 많은 시간을 투입할 수 있다.

### 2. 활용 방안

#### 1) 단기 활용
초기에는 반도체·전자부품 제조라인을 중심으로 파일럿 PoC 적용이 가능하다. 실제 검사 데이터와 현장 피드백을 반영해 판정 정확도와 사용자 경험을 검증할 수 있다. 동시에 엔지니어 교육 도구로 활용해, VQA 챗봇을 통한 불량 패턴 학습과 판정 기준 이해를 지원할 수 있다.

#### 2) 중장기 확장
향후에는 실제 MES/ERP 연동, 멀티 라인 통합 관제, 불량 패턴 누적 학습, 자가검증 파이프라인 고도화로 확장할 수 있다.

| 확장 방향 | 설명 |
|------|------|
| 실제 MES/ERP 연동 | Mock 구조를 실제 운영 API로 교체 |
| 멀티 라인 통합 관제 | 라인별 대시보드 집계, 공장 단위 KPI 제공 |
| 불량 패턴 누적 학습 | 판정 결과 피드백 루프 구축, 모델 지속 개선 |
| 자가검증 고도화 | CoVe 검증 단계를 확장해 더 정교한 판단 구조 구현 |

### 3. 정책 연계성과 산업적 의미
본 플랫폼은 제조 AX 정책, 스마트공장 확산 전략과 자연스럽게 연결된다. 특히 중소·중견 제조기업이 고가의 전용 시스템 없이도 기존 검사 인프라 위에서 AI 기반 품질 관리 체계를 도입할 수 있다는 점에서 실용성이 높다.

또한 CSV 기반 검사 로그, 이미지 기반 검사 프로세스, Mock ERP 구조 등은 업종 공통 포맷과 교육용 플랫폼으로도 발전 가능하다. 즉, 단일 현장 도구를 넘어 제조 데이터 표준화와 엔지니어 AI 리터러시 향상에도 기여할 수 있다.

### 4. 최종 목표
본 플랫폼의 최종 목표는 단순 불량 탐지를 자동화하는 것이 아니다. AI가 검사 결과를 이해하고, 불량 원인을 추정하며, 현장 의사결정과 공정 개선까지 지원하는 제조 AI Agent 플랫폼으로 발전하는 것이다. 이를 통해 제조 현장의 AI 도입 장벽을 낮추고, 반복 불량 대응과 품질 운영의 수준을 실질적으로 높이는 것이 본 제안의 궁극적 지향점이다.
