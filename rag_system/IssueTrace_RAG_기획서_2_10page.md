# IssueTrace RAG 기획서 축약본

**아이디어명**: IssueTrace RAG  
**부제**: 공정거래 의결서 하이브리드 검색·생성 시스템  
**목적**: 28페이지 분량의 기존 기획서를 핵심 내용 중심의 약 10페이지 수준으로 축약한 문서

---

## Ⅰ. 기획 개요

### 1. 서비스 정의
IssueTrace RAG는 공정거래위원회 의결서 데이터를 기반으로 사용자의 자연어 질문에 대해 관련 근거와 요약 답변을 제공하는 법률 특화 검색·생성 시스템이다. 공정거래위원회가 공개한 의결서 500건을 31,879개 청크로 구조화하고, BM25와 Dense Retrieval을 결합한 하이브리드 검색을 통해 적합한 근거를 찾은 뒤, LLM이 이를 바탕으로 답변을 생성한다.

이 서비스의 핵심은 단순 문서 검색이 아니라 "질문-근거-설명" 구조를 갖춘 지능형 탐색 환경을 제공하는 데 있다. 사용자는 법률 용어나 사건명을 정확히 알지 못해도 일상적인 문장으로 질문할 수 있고, 시스템은 관련 선례와 제재 내용을 빠르게 찾아준다.

### 2. 제안 배경
현재 공정거래위원회 의결서는 PDF 또는 HTML 문서 형태로 분산 공개되어 있다. 공개 자체는 이루어지고 있으나, 실제 활용은 제목·날짜 중심의 단순 검색에 머무른다. 문서 분량이 길고 법률 용어가 많아 일반 사용자나 소상공인이 직접 읽고 핵심을 파악하기 어렵다.

이 구조는 세 가지 문제를 만든다.

| 문제 | 설명 |
|------|------|
| 접근성 부족 | 비전문가는 필요한 사건을 찾는 것부터 어렵다. |
| 활용성 부족 | 공개 데이터가 축적되어도 정책·시장·국민에게 실질적으로 환류되지 못한다. |
| 시간 비용 증가 | 법무팀, 연구자, 조사 담당자는 유사 선례 탐색에 많은 시간을 쓴다. |

### 3. 기획 목적
본 기획은 공정거래 의결서를 검색 가능한 AI 자산으로 전환하여 다음 목적을 달성하는 데 있다.

| 목적 | 세부 내용 |
|------|---------|
| 정보 민주화 | 비전문가도 공정거래 관련 제재 사례와 판단 근거를 이해할 수 있도록 지원 |
| 행정 효율화 | 조사·분석·보고 과정에서 유사 선례 탐색 시간을 단축 |
| 데이터 실활용 | 공개 데이터를 단순 보관이 아니라 서비스형 자산으로 전환 |
| 사전 리스크 대응 | 기업과 소상공인이 유사 위반 사례를 사전에 비교·점검 가능 |

## Ⅱ. 문제 정의와 필요성

### 1. 현재 방식의 한계
공정거래 의결서는 공개 범위와 사회적 중요성에 비해 활용성이 낮다. 사용자는 사건명이나 법률 용어를 먼저 알아야 검색이 가능하며, 검색 후에도 수십 페이지 문서를 직접 읽어야 한다. 특히 "이런 행위가 문제인지", "비슷한 사례에서 어떤 제재가 있었는지" 같은 실제적 질문은 기존 방식으로 빠르게 해결하기 어렵다.

또한 공정거래 관련 분쟁은 가맹, 유통, 하도급, 표시광고, 담합 등 다양한 분야에서 반복적으로 발생한다. 소상공인과 일반 소비자는 법률 자문 비용과 정보 접근성의 한계로 인해 사전 대응이 어렵고, 기업 법무팀은 위험 사례를 빠르게 비교할 수 있는 도구가 필요하다.

### 2. 왜 지금 필요한가
LegalTech 시장은 성장 중이지만 공정거래 특화 AI 서비스는 여전히 부족하다. 반면 공정위 의결서는 이미 공개되어 있고, 데이터 규모도 검색·생성형 AI 서비스에 적합하다. 즉, 데이터는 존재하지만 사용 가능한 서비스가 부재한 상태다.

IssueTrace RAG는 이 간극을 해소한다. 기존의 "문서 목록 제공"을 "질문 기반 정보 제공"으로 바꾸어, 공공데이터의 사회적 활용도를 높이고 민간과 공공 모두가 활용 가능한 법률 정보 인프라를 제시한다.

|------|------|------|

| 소상공인·가맹점주 | 본사·거래처 행위의 위반 가능성 점검 | 신고·상담 전 자가 진단 가능 |
| 기업 법무·컴플라이언스 | 유사 위반 선례 및 제재 수준 탐색 | 사전 리스크 관리 강화 |

### 2. 대표 활용 시나리오
첫째, 가맹점주가 판촉비 전가나 계약상 불공정 조건에 대해 질문하면, 시스템은 관련 의결서 청크와 함께 제재 유형을 제시한다. 사용자는 법률 전문가 도움 없이도 자신의 상황과 유사한 선례를 빠르게 확인할 수 있다.

둘째, 기업 법무팀은 특정 영업 행위가 담합 또는 불공정거래행위로 판단된 사례가 있는지 검색해 사전 컴플라이언스 검토 자료로 활용할 수 있다.

셋째, 연구자와 정책 담당자는 특정 위반 유형이나 제재 유형을 기준으로 사례를 빠르게 모아 분석할 수 있다. 이는 단순 질의응답을 넘어 정책·연구 활용으로 확장될 수 있다.

## Ⅳ. 데이터와 시스템 구조

### 1. 데이터 구성
원천 데이터는 fairdata.kr에서 제공되는 공정거래위원회 의결서 500건이다. 문서는 본문과 표를 포함한 하이브리드 JSON 형태로 정리되어 있으며, 이를 기반으로 총 31,879개 청크를 색인했다. 각 청크에는 문서명, 섹션, 청크 유형, 위반 유형, 조치 유형 등 메타데이터가 부여된다.

| 항목 | 내용 |
|------|------|
| 원천 데이터 | 공정거래위원회 의결서 500건 |
| 청크 수 | 31,879개 |
| 청크 유형 | text, table |
| 메타데이터 | 문서명, 섹션, 위반 유형, 조치 유형 등 |

### 2. 전처리 원칙
검색 품질을 높이기 위해 너무 짧은 청크는 제거하고, 과도하게 긴 청크는 분리하여 관리한다. 표와 본문을 구분해 저장함으로써 제재 수치나 과징금 정보 같은 구조화된 내용도 검색 대상에 포함시켰다. 이 과정은 법률 문서의 복잡한 구조를 반영하기 위한 전처리 설계다.

### 3. 시스템 아키텍처
시스템은 크게 데이터 파이프라인, 검색 엔진, 생성 엔진, 웹 인터페이스로 구성된다.

| 구성 요소 | 역할 |
|------|------|
| 데이터 파이프라인 | 원천 데이터 수집, 청크화, 인덱스 및 임베딩 생성 |
| 검색 엔진 | BM25와 Dense Retrieval 병렬 검색, RRF 통합 |
| 생성 엔진 | 근거 청크 기반 답변 생성 |
| UI/서버 | 질문 입력, 결과 표시, 근거 검증 기능 제공 |

## Ⅴ. 핵심 기술 설계

### 1. 하이브리드 검색
IssueTrace RAG는 BM25와 Dense Retrieval을 병렬로 수행한다. BM25는 법조문, 사건명, 고유명사처럼 정확한 키워드 매칭에 강하고, Dense Retrieval은 사용자의 자연어 의도를 반영한 의미 기반 검색에 강하다. 두 방식의 장점을 함께 활용하면 단일 검색 방식보다 정확도와 포괄성을 동시에 확보할 수 있다.

### 2. RRF 기반 통합
두 검색 결과는 Reciprocal Rank Fusion(RRF)으로 통합한다. 이를 통해 특정 검색기에만 편향되지 않으면서 상위 근거를 안정적으로 재정렬할 수 있다. 최종적으로 중복 없는 상위 5개 청크를 생성 모델에 전달해 근거 중심 답변을 구성한다.

### 3. 공정거래 도메인 특화 쿼리 확장
사용자의 질문에는 법률 전문 용어가 포함되지 않는 경우가 많다. 이를 보완하기 위해 공정거래 분야 주요 11개 카테고리의 키워드 사전을 구축하고, 질의에 관련 용어를 자동으로 확장한다. 이 과정은 규칙 기반으로 동작하므로 추가 지연이 거의 없고, 검색 누락을 줄이는 데 효과적이다.

### 4. 생성 모델 운용
개발 환경에서는 Solar-Pro API를 사용하고, 평가 및 오프라인 환경에서는 Qwen2.5-7B-Instruct를 사용한다. 생성 단계에서는 검색된 근거 청크만 활용하도록 프롬프트를 제한해 할루시네이션을 줄이고, 답변과 함께 근거를 사용자에게 직접 제공한다.

## Ⅵ. 사용자 경험과 서비스 화면

### 1. 기본 사용 흐름
사용자는 웹 화면에서 자연어 질문을 입력한다. 시스템은 쿼리 확장, 검색, 답변 생성을 순차적으로 수행하고, 결과 화면에 AI 답변과 근거 청크를 함께 제공한다. 사용자는 답변만 보는 것이 아니라 어떤 문서와 문단을 근거로 삼았는지 바로 확인할 수 있다.

### 2. 화면 구성 원칙

| 화면 요소 | 목적 |
|------|------|
| 질문 입력창 | 자연어 기반 접근성 확보 |
| 예시 질문 | 서비스 활용 방식 이해 지원 |
| 단계별 진행 표시 | 검색·생성 상태 가시화 |
| AI 답변 카드 | 핵심 결과 빠른 확인 |
| 근거 Top-5 카드 | 답변 신뢰성 검증 |
| 청크 상세 보기 | 문서명, 섹션, 메타데이터 확인 |

### 3. UX 차별점
일반적인 검색 서비스가 결과 목록만 보여주는 데 비해, IssueTrace RAG는 "근거 중심 답변"을 제공한다. 사용자는 요약 결과와 근거 원문을 동시에 확인할 수 있어 법률 정보 서비스에서 중요한 설명 가능성과 검증 가능성을 확보할 수 있다.

## Ⅶ. 구현 및 배포 전략

### 1. 구현 환경
시스템은 Python 3.11 기반으로 구성되며, 검색과 생성 모듈은 분리된 구조를 갖는다. BM25 인덱스, 임베딩 벡터, 코퍼스 파일을 로컬에 저장하고, FastAPI 기반 API 서버를 통해 질의응답을 제공한다.

### 2. 오프라인 대응
평가 및 실제 활용 환경에서 네트워크 제약이 있을 수 있으므로, 외부 벡터 데이터베이스 없이 NumPy 기반 임베딩 검색 구조를 채택했다. 또한 로컬 LLM을 포함한 Docker 이미지 형태로 배포가 가능해 폐쇄망 환경에서도 동작할 수 있다.

### 3. 운영 안정성
대규모 임베딩 생성 시 체크포인트를 두어 중단 후 재개가 가능하도록 설계했고, 검색 단계와 생성 단계를 분리해 장애 원인 파악과 유지보수가 쉽도록 했다. 이는 실증형 AI 서비스 운영에 필요한 기본 안정성 요건을 충족한다.

## Ⅷ. 기대 효과

### 1. 국민과 소상공인 관점
법률 지식이 부족한 사용자도 공정거래 피해 유형과 제재 선례를 빠르게 이해할 수 있다. 이는 법률 정보 접근의 형평성을 높이고, 사후 대응보다 사전 인지와 예방에 도움을 준다.

### 2. 기업 관점
기업은 유사 제재 사례를 참고해 내부 정책과 가이드라인을 강화할 수 있다. 특히 담합, 불공정거래, 유통·가맹 관련 리스크를 사전에 점검하는 실무 도구로 활용 가능하다.

### 3. 공공과 연구 관점
정책 담당자와 연구자는 방대한 의결서 데이터를 구조적으로 탐색할 수 있어 분석 업무 효율이 높아진다. 공공데이터의 공개를 넘어 활용 단계까지 연결된다는 점에서 정책적 의미도 크다.

## Ⅸ. 향후 확장 방향

### 1. 기능 확장
향후에는 위반 유형별 필터 검색, 사건 비교 리포트, 통계 대시보드, 제재 수준 시각화 기능을 추가할 수 있다. 이를 통해 질의응답 중심 서비스에서 분석형 플랫폼으로 확장할 수 있다.

### 2. 데이터 확장
공정거래 분야 외에도 하도급법, 가맹사업법, 전자상거래법 등 인접 법률 분야로 확장할 수 있다. 현재 구조는 다른 법률 문서군에도 재사용 가능한 파이프라인을 갖고 있어 확장성이 높다.

### 3. 서비스화 전략
초기에는 공공데이터 활용 데모 및 실증 서비스로 운영하고, 이후에는 공공기관 협업, 법률 정보 플랫폼 연계, 기업용 컴플라이언스 도구로의 사업화를 검토할 수 있다.

## Ⅹ. 결론

IssueTrace RAG는 이미 공개되어 있지만 활용되기 어려운 공정거래 의결서 데이터를, 실제 질문에 답할 수 있는 AI 서비스로 전환하는 기획이다. 핵심 경쟁력은 공정거래 특화 데이터 전처리, 하이브리드 검색, 근거 중심 생성, 오프라인 배포 대응에 있다.

이 기획은 단순한 검색 고도화가 아니라 공공 법률 데이터를 국민과 기업, 공공기관 모두가 활용할 수 있는 실질적 정보 서비스로 전환한다는 점에서 의미가 있다. 따라서 본 프로젝트는 공공데이터 실활용, 국민 체감형 AI 서비스, 법률 정보 접근성 개선이라는 세 가지 목표를 동시에 충족하는 실행 가능성이 높은 과제로 평가할 수 있다.
