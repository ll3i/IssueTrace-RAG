## Ⅰ. 기획서 개요

### 1.1 아이디어 기획 분야 및 목적

#### 서비스 분야

본 아이디어는 **데이터·기술 혁신 트랙**과 **국민 체감형 서비스** 두 분야에 동시에 해당한다. 공정거래위원회가 공개한 의결서 데이터를 AI 기술로 가공하여, 일반 국민·소상공인·기업 법무팀·연구자 등 다양한 사용자가 자연어로 공정거래 정보를 즉시 조회할 수 있는 실용 서비스를 구현한다.

#### 핵심 내용

공정거래위원회는 매년 수백 건의 의결서를 공개하고 있으나, 해당 문서는 PDF·HTML 형태로 분산 게시되어 키워드 검색 외의 활용이 사실상 불가능하다. 법률 전문용어로 작성된 의결서를 비전문가가 스스로 찾아 읽고 이해하는 데는 상당한 시간과 전문 지식이 요구된다.

**IssueTrace RAG**는 이 문제를 해결하기 위해 의결서 500건 전체를 **31,879개 청크**로 분할·색인하고, 사용자가 자연어로 질문을 입력하면 **관련 근거 청크 5개와 AI 생성 답변**을 30초 이내에 반환하는 하이브리드 검색·생성(RAG) 시스템이다.

기술적으로는 **BM25 희소 검색**과 **Solar Dense 임베딩 검색**을 병렬 수행한 뒤 **Reciprocal Rank Fusion(RRF)**으로 통합 재정렬하는 하이브리드 아키텍처를 채택하였다. 단일 방식 대비 법률 도메인 검색 정확도를 유의미하게 향상시킬 수 있다.

#### 목적

| 목적 | 세부 내용 |
|------|---------|
| 정보 민주화 | 법률 전문가 없이도 누구나 공정거래 의결서 내용을 자연어로 조회 |
| 행정 효율화 | 공정위 조사관·연구자의 유사 선례 검색 시간 단축 |
| 데이터 실활용 | 페어데이터 의결서 데이터셋을 AI 서비스로 전환하여 실질 가치 창출 |
| 불공정 억제 | 기업·소상공인이 자사 행위와 유사 제재 사례를 사전 비교하여 컴플라이언스 강화 |

### 1.2 배경 및 필요성

#### 제안 배경

**공정거래위원회 의결서의 공개 현황과 한계**

공정거래위원회는 독점규제 및 공정거래에 관한 법률 제116조에 따라 의결서를 공개할 의무가 있으며, 이를 페어데이터(fairdata.kr) 및 공정위 공식 홈페이지를 통해 게시하고 있다. 현재 공개된 의결서는 500건 이상으로, 담합·시장지배적 지위남용·불공정거래행위·기업결합 등 다양한 위반 유형을 망라한다.

그러나 현재의 공개 방식에는 다음과 같은 구조적 한계가 존재한다.

| 한계 | 구체적 문제점 |
|------|-------------|
| **분산 게시** | 개별 PDF·HTML 파일로 제공, 통합 검색 불가 |
| **키워드 의존** | 제목·날짜 기반 검색만 가능, 내용 의미 검색 미지원 |
| **전문성 장벽** | 법률 용어·사건 구조가 복잡하여 비전문가 접근 어려움 |
| **AI 미적용** | 검색 결과를 요약하거나 답변을 생성하는 AI 서비스 부재 |
| **활용 저조** | 방대한 데이터가 쌓이나 실질적 정보 활용률이 낮음 |

**사회적 수요**

- 공정거래위원회 신고 건수는 연간 수천 건 수준이며, 신고 전 유사 사례를 직접 검토하고자 하는 수요가 상존한다.
- 가맹사업법, 대규모유통업법, 하도급법 등 소상공인 관련 법률 위반 제재가 증가 추세로, 소상공인의 법률 정보 접근 필요성이 높아지고 있다.
- 기업 ESG·컴플라이언스 의무 강화로 법무팀의 위반 선례 검색 도구 수요가 증가하고 있다.
- 국내 LegalTech 시장은 연평균 20% 이상 성장 중이나, 공정거래 특화 AI 검색 서비스는 아직 공백 상태이다.

#### 검색 계층 상세 설계

**① 쿼리 확장 (QueryExpander)**

공정거래 법률 도메인 특화 쿼리 확장 모듈로, LLM 없이 규칙 기반으로 동작하여 추가 레이턴시가 없다.

| 카테고리 | 확장 키워드 예시 |

**② BM25 희소 검색**

```python
# 토크나이저: 공백 분리 + 문자 2-gram 혼합
def tokenize(text):
    tokens = text.split()           # 어절 단위
    bigrams = [text[i:i+2]          # 문자 2-gram
               for i in range(len(text)-1)]
    return tokens + bigrams

# BM25Okapi 색인 (rank-bm25 라이브러리)
bm25 = BM25Okapi(tokenized_corpus)
scores = bm25.get_scores(tokenized_query)
# → top-20 후보 선정
```

형태소 분석기(konlpy 등) 없이 공백+2-gram 토크나이저를 사용하여 의존성을 최소화하고, 법률 고유명사(기업명, 법조항 번호 등)의 정확한 매칭을 보장한다.

**③ Dense 임베딩 검색 (Solar Asymmetric Embedding)**

비대칭 임베딩 전략을 통해 문서와 질의의 의미 공간을 각각 최적화한다.

| 구분 | 모델 | 용도 |
|------|------|------|
| 문서(색인 시) | `solar-embedding-1-large-passage` | 의결서 청크 벡터화, 의미 압축 최적화 |
| 쿼리(검색 시) | `solar-embedding-1-large-query` | 질의 벡터화, 질의 의미 표현 최적화 |

```python
# 벡터 저장: float16, 31879×4096 행렬, 249MB
embeddings = np.load("embeddings.npy")  # float16

# 검색: L2 정규화 후 행렬 내적(코사인 유사도)
query_vec = normalize(embed_query(expanded_query))
scores = embeddings @ query_vec          # 행렬 내적
top20_idx = np.argsort(scores)[-20:]    # top-20 선정
```

ChromaDB 등 외부 벡터 데이터베이스 없이 numpy 행렬 연산만으로 고속 검색을 구현하여, 오프라인 환경에서도 추가 의존성 없이 동작한다.

**④ Reciprocal Rank Fusion (RRF)**

BM25와 Dense 검색 결과를 하나의 순위로 통합한다.

```
RRF 점수(d) = Σ  1 / (k + rank_i(d))
              i∈{BM25, Dense}

k = 60 (표준 설정)

- BM25 top-20: rank 1~20
- Dense top-20: rank 1~20
- 합산 후 내림차순 정렬 → Top-5 chunk_id 선정
- 중복 chunk_id 자동 제거 보장
```

| 환경 | 모델 | 방식 |
|------|------|------|
| 개발·데모 | Solar-Pro API (Upstage) | REST API 호출 |
| 오프라인 평가 | Qwen2.5-7B-Instruct (로컬) | HuggingFace transformers, device_map="auto" |

```
[시스템 프롬프트]
당신은 공정거래위원회 의결서 전문 AI입니다.

...

[사용자 질문]

## Ⅲ. 문제정의

### 3.1 문제 정의 및 해결 방안

#### 핵심 문제 3가지

**문제 1: 정보 비대칭 — "있어도 못 쓰는 데이터"**

공정거래위원회 의결서는 법적으로 공개 의무가 있어 게시되고 있으나, 실질적인 활용도는 매우 낮다. 비전문가가 특정 위반 유형의 선례를 찾으려면 수십~수백 건의 의결서 제목을 일일이 확인하거나 법률 자문에 의존해야 한다. 공개된 데이터가 있음에도 접근 장벽 때문에 정보가 사회적으로 환류되지 못하는 전형적인 정보 비대칭 상황이다.

**문제 2: 단순 키워드 검색의 한계 — "뭘 검색해야 할지 모름"**

공정위 홈페이지의 의결서 검색은 제목과 날짜 기반의 단순 키워드 매칭만 지원한다. 사용자가 "편의점 본사가 판촉비를 떠넘기는 행위"를 검색하려 해도, 의결서 제목에 "판촉비 떠넘기기"라는 표현이 없으면 결과가 나오지 않는다. 사용자가 법률 용어(예: "대규모유통업법", "판매촉진비용 분담")를 미리 알아야 검색이 가능한 구조이다.

**문제 3: 답변 생성 부재 — "찾아도 읽기 어렵다"**

검색에 성공하더라도 의결서 한 건은 평균 수십 페이지에 달하는 방대한 법률 문서이다. 사용자가 원하는 정보(예: 과징금 금액, 위반 행위 판단 기준)가 어느 섹션에 있는지 파악하는 것 자체가 전문가 수준의 능력을 요한다. AI가 핵심 내용을 요약하여 자연어 답변으로 제공하는 기능이 필요하다.

#### 해결 방안: Hybrid RAG

| 문제 | 해결 방안 | 적용 기술 |
|------|----------|---------|
| 정보 비대칭 | 전체 의결서 청크 색인 → 자연어 질문 즉시 답변 | BM25 + Dense + RRF |
| 키워드 검색 한계 | 의미 기반 검색 + 도메인 쿼리 확장 | Solar 임베딩 + 키워드 사전 |
| 답변 생성 부재 | 검색된 청크를 근거로 LLM 핵심 요약 생성 | Solar-Pro / Qwen2.5-7B |
| 전문 용어 장벽 | 쿼리 자동 확장으로 법률 용어 보완 | 11개 카테고리 규칙 사전 |
| 근거 불명확 | Top-5 근거 청크 함께 제공, 원문 확인 가능 | 청크 상세 모달 UI |

### 3.2 핵심 기능 설명

#### 기능 1: 하이브리드 검색 (BM25 + Dense + RRF)

단일 검색 방식의 약점을 상호 보완하는 하이브리드 아키텍처를 채택한다.

| 방식 | 강점 | 약점 |
|------|------|------|
| BM25 (키워드) | 정확한 단어 매칭, 기업명·법조항 번호 검색 | 동의어·의미적 유사어 미인식 |
| Dense (임베딩) | 의미 유사도 검색, 표현이 달라도 관련 문서 검색 | 희귀 고유명사 약함, 속도 |
| RRF 결합 | 두 방식의 강점을 통합, 안정적 성능 | — |

RRF(k=60)를 통해 두 목록을 결합하면, BM25에서 높은 순위를 차지한 청크와 Dense에서 높은 순위를 차지한 청크 모두 상위에 배치되어, 단일 방식 대비 다양한 질문 유형에 강건하게 대응할 수 있다. 항상 중복 없는 정확히 5개의 chunk_id를 반환하도록 서버 단에서 검증한다.

#### 기능 2: 공정거래 도메인 특화 쿼리 확장

사용자가 입력한 질문에 공정거래 법률 키워드를 자동으로 보강한다. LLM 호출 없이 사전 기반 규칙으로 동작하여 레이턴시가 없다.

**동작 예시**
```
입력: "편의점 본사가 판촉비를 가맹점에 떠넘기는 행위"

확장 결과:
- 원본 질문 유지
- 추가: "판매촉진비용 불공정거래행위 대규모유통업 납품업자
         가맹점 가맹본부 가맹사업법 시정명령 과징금"
- 기업명 패턴 감지 시 추가: "의결서 피심인 위반행위"

→ BM25·Dense 검색 쿼리로 확장된 텍스트 사용
```

11개 카테고리 × 평균 8개 키워드 = 약 90개 법률 용어 사전을 내장하고 있어, 일반인의 구어체 표현과 법률 전문 용어 간의 간극을 자동으로 연결한다.

#### 기능 3: 비대칭 Solar 임베딩 + Numpy 벡터 저장소

문서 임베딩과 쿼리 임베딩에 각각 특화된 모델을 사용하는 **비대칭(Asymmetric) 임베딩** 전략을 채택한다.

- **문서 임베딩(색인 시)**: `solar-embedding-1-large-passage` — 의결서 본문의 의미를 4,096차원으로 압축·저장
- **쿼리 임베딩(검색 시)**: `solar-embedding-1-large-query` — 사용자 질문의 의도를 같은 공간에 매핑

두 모델이 동일한 벡터 공간을 공유하지만 각자의 역할에 최적화되어 있어, 대칭 임베딩 대비 문서-질의 매칭 정확도가 향상된다.

벡터 저장소는 ChromaDB·Milvus 등 외부 데이터베이스 없이 NumPy `.npy` 파일 하나(float16, 31,879×4,096 = 249MB)로 구현하였다. 서버 시작 시 전체 행렬을 메모리에 로드하고, 쿼리마다 행렬 내적 한 번으로 전체 청크와의 코사인 유사도를 동시 계산한다. 오프라인 환경에서 외부 의존 없이 완전 동작하며, 벡터 검색 속도도 수십 ms 수준으로 유지된다.

#### 기능 4: 웹 대시보드 UI

평가 API(`/predict`)와 별도로, 시스템을 직관적으로 시연·검증할 수 있는 웹 UI를 단일 HTML 파일(`static/index.html`)로 제공한다.

주요 기능:
- **예시 질문 8개(4×2 그리드)**: 클릭 한 번으로 다양한 검색 시나리오 즉시 실행
- **단계별 진행 표시**: 쿼리 확장 → 임베딩 검색 → 답변 생성 순서로 시각화
- **근거 청크 카드**: 각 청크의 순위, 문서명, 섹션, 본문 미리보기를 카드 형태로 표시
- **청크 상세 모달**: 카드 클릭 시 전체 텍스트 및 위반 유형·조치 유형 태그 확인
- **Chunk ID 복사**: 평가 제출 시 chunk_id를 클립보드에 바로 복사
- **검색 히스토리**: 이전 검색 질문을 사이드바에 기록, 클릭 시 재실행

    사례가 있나요?"

   원본 + "판매촉진비용 불공정거래행위 대규모유통업법

4. Dense 검색 (top-20):
   판촉비 부담 전가 의미 유사 청크 추가 포함

5. RRF 통합 → Top-5 청크 선정:
   - CH-042: BGF리테일 위반 행위 판단 섹션
   - CH-043: 판매촉진비용 50% 초과 사실 인정
   - CH-091: 대규모유통업법 제11조 조문
   - CH-107: 과징금 산정 근거
   - CH-155: 시정명령 주문

6. AI 답변 생성:
   "BGF리테일(주)는 2019년부터 2021년까지 납품업자에게
    판매촉진비용의 50%를 초과하여 부담시킨 행위가
    대규모유통업법 제11조 위반으로 인정되어,
    공정거래위원회로부터 시정명령 및 과징금이 부과되었습니다.
    판매촉진비용을 50% 초과하여 납품업자에게 전가하는 행위는
    법 위반에 해당하므로, 귀하의 사례도 신고를 검토해 보시기 바랍니다."

7. A씨 행동:
   - 근거 청크 5개 클릭 → 원문 확인
   - Chunk ID 복사 → 공정위 신고 시 근거 자료로 활용
```

   과징금 부과 관련 매출액 부과율 감경 가중"

5. B씨 활용:

### 3.5 결과 해석 및 시사점

#### 차별성 및 독창성

| 항목 | 기존 방식 | IssueTrace RAG | 차별점 |
|------|----------|---------------|-------|
| 검색 방식 | 제목 키워드 매칭 | BM25 + Dense 하이브리드 + RRF | 의미 검색 + 정확 매칭 동시 지원 |
| 도메인 적응 | 범용 검색 | 공정거래 11개 카테고리 쿼리 확장 | 추가 레이턴시 없는 도메인 특화 |
| 임베딩 전략 | 단일(대칭) 임베딩 | 비대칭 passage/query 분리 | 문서-질의 의미 공간 정확도 향상 |
| 벡터 저장소 | ChromaDB 등 외부 DB | NumPy .npy 자체 구현 | 오프라인 완전 동작, 의존성 최소 |
| 답변 제공 | 문서 목록 링크 | 근거 기반 자연어 답변 생성 | 비전문가도 즉시 이해 가능 |
| 배포 | 인터넷 연결 필요 | 완전 오프라인 Docker 컨테이너 | 폐쇄망 평가 환경 대응 |

#### 성능 및 시사점

- **BM25의 효과**: 법률 문서는 고유명사(기업명, 법조항 번호)가 핵심 검색 키워드인 경우가 많아, 형태소 분석기 없는 2-gram BM25도 경쟁력 있는 검색 성능을 발휘한다. OFFLINE_MODE에서도 BM25 단독으로 의미 있는 결과를 반환한다.
- **비대칭 임베딩의 효과**: 동일 모델을 문서·쿼리 양쪽에 사용하는 대칭 방식 대비, passage/query 분리 모델이 법률 질의응답의 정확도를 향상시킨다.
- **도메인 전처리의 중요성**: 쿼리 확장, 청크 메타데이터 구조화, 텍스트/표 유형 구분 등 공정거래 특화 전처리가 검색 품질의 결정적 요인이다.

## Ⅳ. 데이터 활용 계획

### 4.1 기본 방향

**원칙 1 — 전량 활용**: 공개된 의결서 500건 전체를 예외 없이 청크 단위로 분할하여 검색 가능한 형태로 색인한다. 특정 분야·연도만 선별하는 편향을 배제하여 검색 커버리지를 최대화한다.

**원칙 2 — 구조 보존**: hybrid.json의 청크 구분(text/table), 섹션명, 문서 제목 등 메타데이터를 색인 단계에서 그대로 보존한다. 이를 통해 검색 결과에서 정확한 근거 섹션 위치를 함께 제공할 수 있다.

**원칙 3 — 지속 확장성**: 신규 의결서가 추가되더라도 `build_index.py`와 `build_numpy_index.py`를 재실행하여 코퍼스 및 인덱스를 갱신할 수 있는 파이프라인을 구현하였다. 체크포인트 방식으로 Dense 임베딩 빌드를 중단·재개할 수 있어 대량 데이터 추가에도 대응 가능하다.

**원칙 4 — 품질 관리**: 빈 텍스트(10자 미만) 필터링, 8,000자 초과 청크 길이 제한, float16 정밀도 유지 등의 품질 기준을 일관되게 적용하여 임베딩 품질과 검색 안정성을 확보한다.

#### 청크 분할 전략

| 항목 | 설계 내용 |
|------|---------|
| 원천 단위 | hybrid.json의 chunks 배열 (문서 구조 그대로 활용) |

| 최대 길이 | 8,000자 초과 시 분할 또는 앞부분만 사용 |
| 인코딩 | UTF-8, 한국어 특수문자 보존 |

| 단계 | 모델 | 차원 | 정밀도 | 용도 |
|------|------|------|--------|------|
| 색인(문서) | solar-embedding-1-large-passage | 4,096 | float32 → float16 저장 | 의결서 청크 벡터화 |
| 검색(쿼리) | solar-embedding-1-large-query | 4,096 | float32 | 질문 벡터화 (실시간) |

저장된 임베딩은 float16(반정밀도)으로 압축하여 249MB를 유지하면서도, 코사인 유사도 계산 시에는 float32로 업캐스팅하여 정밀도 손실을 최소화한다.

## Ⅴ. 기대 효과

### 5.1 국민 관점

**정보 접근 민주화**
법률 전문가 없이도 공정거래 피해 유형·제재 결과를 자연어로 즉시 조회할 수 있어, 법률 서비스의 비용 장벽을 낮추고 정보 접근의 형평성을 높인다. 특히 법률 자문 비용을 감당하기 어려운 소상공인·일반 소비자에게 실질적 혜택이 돌아간다.

**소비자 권리 강화**
불공정 피해를 인식한 소비자가 유사 제재 사례를 즉시 검색·확인함으로써 신고 의향이 높아지고, 권리 행사의 실질화가 기대된다. 시스템이 근거 청크를 함께 제공하므로 사용자가 AI 답변의 신뢰도를 직접 검증할 수 있어 할루시네이션 피해를 방지한다.

**사회적 신뢰 제고**
AI가 생성한 답변이 아닌, AI가 **근거 문서를 찾아 요약**하는 방식이므로, 출처를 투명하게 제시하고 사용자가 직접 원문을 확인할 수 있다. 이는 법률 도메인 AI에 대한 신뢰를 높이는 데 기여한다.

### 5.2 기업 관점

**리스크 조기 감지 및 컴플라이언스 비용 절감**
기업 법무팀이 동종 업종 위반 사례와 과징금 기준을 즉시 검색할 수 있어, 사전 컴플라이언스 점검에 소요되는 시간과 외부 법률 자문 비용을 줄일 수 있다. 담합·불공정거래행위 등 위반 가능성이 있는 행위를 사전에 인식하고 내부 가이드라인을 강화하는 데 활용할 수 있다.

**공정 경쟁 촉진**
기업이 자사 행위와 유사한 제재 선례를 쉽게 확인할 수 있게 됨으로써, 무지에서 비롯된 의도치 않은 위반 행위가 줄어들고 시장의 공정 경쟁 문화가 형성될 것으로 기대된다.

### 5.3 정부 관점

**행정 효율화**
공정위 조사관이 유사 선례를 신속하게 검색할 수 있어 사건 조사의 일관성과 효율성이 향상된다. 의결서 작성 시 유사 사건의 판단 기준을 참조하는 데 소요되는 시간을 단축할 수 있다.

**데이터 활용 실증 모델**
공개 데이터가 AI 서비스로 전환되어 실질적 사회 가치를 창출하는 모범 사례가 된다. 향후 다른 정부 부처의 법률 데이터(공정위 심결, 조세심판원 결정문 등)에도 같은 방식을 적용하는 데 참조 모델로 활용될 수 있다.

**정책 인텔리전스**
시스템에 쌓이는 검색 질문 패턴을 분석하면, 국민이 어떤 위반 유형에 관심이 높은지, 어떤 정보 격차가 존재하는지 파악하여 정책 우선순위 도출과 정보 공개 방식 개선에 활용할 수 있다.

## Ⅵ. 기타 사항

### 건의 사항

#### 1. 추가 데이터 제공 요청

| 요청 데이터 | 기대 효과 |
|-----------|---------|
| 공정위 심결·고시·예규 | 의결서와 함께 색인 시 법령 해석 근거까지 포함한 검색 가능 |
| 위반 유형·과징금이 정형화된 구조화 데이터(CSV) | 메타데이터 기반 필터 검색 기능 추가 가능 |
| 심판 결정문·재결 데이터 | 행정 불복 사례까지 포괄하는 완전한 법률 검색 가능 |
| 신규 의결서 API | 의결서 게시 시 자동 색인 연동 파이프라인 구축 가능 |

#### 2. 서비스 고도화 방안

- **Reranker 적용**: Cross-Encoder 기반 Reranker 추가 시 MRR(Mean Reciprocal Rank) 점수를 추가 향상시킬 수 있다.
- **메타데이터 필터 검색**: 위반 유형·기업명·연도 기반 필터링 UI 추가로 탐색형 검색 지원 가능.
- **신규 의결서 자동 색인**: 공정위 RSS/API 연동 → 신규 의결서 자동 전처리 및 인덱스 갱신 파이프라인 구현.
- **다국어 지원**: 외국계 기업 관련 의결서 또는 국제 카르텔 사건 대응을 위한 영문 검색 확장.
